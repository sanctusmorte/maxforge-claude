# Рабочий процесс: worktree на задачу, параллельные субагенты, один PR

Основной путь для нетривиальной задачи это `/maxforge-claude:task` (`skills/task/SKILL.md`).

1. **Триаж.** Новый проект (`skills/project-new`) или задача в существующем репозитории; быстрая или полная по размеру.
2. **Спецификация.** `skills/spec` изучает репозиторий, фиксирует допущения, задаёт только решающие вопросы и пишет план.
3. **Разбиение по владению файлами.** Сначала пишутся файл общего контракта и заглушки. На каждый независимый блок один агент, у каждого свой worktree, ветка, временный каталог и тестовая база. Пересекающиеся файлы значат одного агента.
4. **Параллельные волны.** Блоки стартуют одновременно; зависимый блок стартует, как только его зависимость запушена. Предел параллельности самого Claude Code задаёт `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`; `settings/recommended.json` ставит 10.
5. **Интеграционная ветка.** PR блоков вливаются в `task/<slug>`.
6. **Ревью и проверка.** Один независимый проход `code-reviewer` (плюс `security-reviewer`, если дифф касается авторизации, загрузок, оплаты, вебхуков или секретов), затем агент `verifier` пытается опровергнуть результат.
7. **Один PR** в интеграционную ветку. Слияние в `main` это отдельное решение о релизе.

## Экраны и продающие страницы

- Экраны приложения: `/maxforge-claude:ui-task` (`skills/ui-task/SKILL.md`): сначала дизайн-система, референсы и план для новых экранов, сборка, `ui-qa`, `dead-clicks`, один вердикт `design-judge`.
- Лендинг, цены, регистрация: `/maxforge-claude:site` (`skills/site/SKILL.md`): бриф, позиционирование, текст, архитектура, затем визуал; на каждом этапе подпись.

## Непрерывность

У каждой задачи есть `progress.md` (`skills/handoff`). Хук PreCompact обновляет и коммитит его; хук SessionStart подставляет его обратно после сжатия или возобновления. Субагент, дошедший до ограды контекста, пишет файл передачи и возвращает `FENCE-HANDOFF <путь>`, и вызывающий продолжает со свежим агентом.

## Уроки

Когда вы поправляете агента, `hooks/lesson-capture.py` помечает это, а `skills/lesson` записывает, что было неверно, что верно и какая проверка поймает повтор.

Общая форма этих правил процесса лежит в `extras/rules/core.md`.
